# 三模块反馈写作标准

这份标准来自教师提供并认可的历史作品，用于下一版生成质量校准。重点是保留具体观察、掌握层次、解题困难与建议之间的关系。输入仍可在一个框中用短句混写，不增加必填项目。

## 筛选结果

每个模块保留两份代表案例，共六份。内置材料使用 `【学生】` 占位，去除姓名、日期和课次；没有将整批作品或学生身份资料写入仓库。

| 模块 | 选入的案例 | 作为标准的价值 |
| --- | --- | --- |
| 一对一 | 第 8 次综合练习稿，涵盖解析几何、数列和概率 | 知识点清楚；区分能提取信息与不会后续变形；建议逐项回应特殊情况、变形和漏情况问题。 |
| 一对一 | 第 6 次等差数列专项稿 | 展示基础和常见题型已掌握时，怎样写特殊性质、条件加工和函数视角的进一步学习要求。 |
| 晚辅 | 作业效率较高、数学基础较好，但方法选择及理化稳定性需加强的稿件 | 把速度、质量、各科学习困难分开，建议具体到方程解法、实验表述和知识应用。 |
| 晚辅 | 数理基础薄弱、面对作业畏难并减少思考投入的稿件 | 展示学习困难与习惯问题共存时的表达；从基础题起步，避免空泛鼓励或人格标签。 |
| 班课 | 基础较扎实、少量提示后能继续独立推导的稿件 | 准确保留“少量提示后继续”的掌握层次，不能统一改写为听完完整讲解后订正。 |
| 班课 | 知道性质但应用不熟、习惯用特殊例子判断的稿件 | 具体定位知识应用方式，体现怎样把困难转成可操作的复盘和推导建议。 |

选择依据是教学信息的代表性和互补性。多个班课稿件重复了相同课程概述及基本不等式建议，只保留最能展示不同掌握层次的两例；一对一另一篇数列综合练习稿与入选稿的方法分析重叠较多，先不重复放入。其余作品仍适合做未放进提示词的效果检查材料，不代表质量较差。

入选输出保留原稿结构、教师口吻和具体分析，适度合并重复句、减少空泛的“熟悉、理解、巩固”。对建议作适当展开时明确采用建议语气，不添加新的课堂表现、分数、进步、已布置任务或既成措施。

## 如何使用

内置资料在 `backend/app/services/feedback_standards.py`，包含：

- `MODULE_STANDARDS`：三类反馈各自的结构、语气、详略和事实边界。
- `MODULE_EXAMPLES`：每类两组短记录与目标反馈，只取当前模块的示例。

**示例中的短输入由认可成稿逆向提炼，仅用于首轮校准。** 它们不是当时留存的原始笔记，也不能证明真实短输入已经达到同样效果。测试时应继续使用未加入提示词的案例和日常实际记录，检查少量输入是否足以生成可用反馈。

示例只说明如何组织语言和展开建议，其中的课程、能力、行为和任务均不属于当前学生。个人风格参考可以继续调整表达偏好，但不能带入范文事实。当前记录里的“可能”“从交流中判断”等来源与不确定性要保留。

## 三类输出的区别

- 一对一以学习内容、表现与掌握、课后建议、实际作业四部分为骨架，保留图标和编号；没有依据的课程或作业部分自然省略，不编造、不写空白占位。
- 晚辅采用紧凑的周反馈，依次组织已观察到的习惯、作业和分科情况，再给对应建议；不用一对一的四个板块。
- 班课采用共用课程概述、个人表现分析和编号建议。同班课程概述可以一致，个人掌握情况和困难必须来自各自记录。

常规篇幅按信息多少和各模块的范文深度展开，不统一限制在 250–400 字；信息少时自然简写。简短模式仍应保留掌握层次、主要问题和对应建议。

## 生成后的自动复核

教师只需一次点击，后台先生成初稿，再用同一配置模型对照当前记录复核。正常每位学生有两次模型调用，费用和等待时间相应增加，但不新增输入项或人工中间步骤。

复核重点是学生事实是否有来源、掌握程度是否被夸大、建议是否对应困难，以及学科建议是否准确。初稿和范文都不是事实来源；复核应保留正确、具体的内容，只修正必要之处。自动复核仍可能遗漏问题，最终由教师核对。

若第二次调用失败，保留初稿并提示自动检查未完成，结果保持未核对，不丢弃已生成内容。该机制不等于实际文案质量已经验收通过，具体运行情况见 [验证记录](VERIFICATION.md)。

## 检查标准

评价生成结果时，重点检查：

1. 是否遗漏或新增学生事实；是否把别人的范文事实带入。
2. 是否保留独立完成、提示后完成、讲解后订正等掌握层次。
3. 是否准确定位困难，避免把方法应用问题笼统写成基础差。
4. 建议是否对应已知问题，并明确属于后续建议。
5. 三个模块是否符合各自格式，语气是否平实自然。
6. 教师还需修改多少事实和措辞，输入及核对是否确实省时。

提示词检查、接口测试和模型实际生成质量应分开记录。示例文字较长或格式相似，都不能单独证明反馈已经达到可直接使用的标准。
