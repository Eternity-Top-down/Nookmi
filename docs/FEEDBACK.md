# 课程反馈使用说明

适用版本：v0.7.0。当前目标是稳定生成高质量反馈，并尽可能减少用户输入。老师只提供真实课程内容和学生具体情况，不必先写成完整反馈，也不必逐栏填完亮点、困难和建议。系统优先按已保存的个人范文写作；未设置时使用三个模块的精选默认标准。

## 三个模块怎样使用

| 模块   | 反馈周期 | 建议输入                                                                 |
| ------ | -------- | ------------------------------------------------------------------------ |
| 一对一 | 每次课   | 本次教学内容、课堂状态、掌握较好或困难的地方、复习建议与作业任务         |
| 晚辅   | 每周     | 本周作业、纪律与心态、闪光点、作业暴露的问题，以及需要家长协助的具体习惯 |
| 班课   | 每月     | 本月共用课程内容、各学生课堂表现与练习反映的掌握情况、下一阶段建议       |

晚辅可按实际情况选择学科，例如初二数学与物理、初三数学与物理及化学。周期起止日期均可调整。

## 从关键词到可发送的反馈

1. 一对一先进入学生；晚辅和班课先进入班级。
2. 核对默认周期和学科；教学内容、关注重点及任务按实际情况选填。一对一只有一份「课后任务」；晚辅和班课分别保留共用任务与个人任务。
3. 在「课堂状态与掌握情况」或「学生情况」主框中记几条真实要点，亮点、困难和建议可以写在一起，不必逐项填写。班级共用课程内容只需填写一次。
4. 晚辅和班课的所有学生在同一页面展开，直接连续填写，不用逐人切换。填完后批量生成，有失败的学生可以单独重试。
5. 阅读生成正文，核对事实、语气和建议，修改后标记已核对。
6. 查看保存状态，复制个人或全班已核对反馈；晚辅、班课也可输入标题导出 Word，再自行发送。

没有完整正文也可以保存：共用内容或学生事实中有有效文字即可形成草稿。日期和学科选择本身不算有效内容。

一对一旧记录如果同时存在共用任务和个人任务，打开后会合并到唯一的课后任务输入框，原有两份内容都能继续查看和编辑。

「补充细节」中的亮点、困难和后续建议均为选填，需要分类记录时再展开；已有内容会自动展开显示，继续保留并参与生成。晚辅仍可按实际观察补充分科情况。

## 默认生成标准

新建反馈默认选择「按范文完整展开」，依据实际信息多少展开，不统一压缩为 250–400 字；资料少时也不凑篇幅。需要短反馈时可以选择「简短，抓住重点」，旧反馈保留原来的篇幅设置。

系统已从教师认可的作品中筛选六份匿名范例，每个模块两份，供没有个人范文时使用：一对一保留学习内容、表现与掌握、后续建议和实际作业的骨架；晚辅采用紧凑周反馈，只分析有记录的学科；班课先写阶段共用课程，再写个人表现和编号建议。具体选材和标准见 [反馈写作标准](WRITING_STANDARDS.md)。

默认一对一仅在板块标题使用图标，按课程信息稳定选择语义匹配的搭配，保持标题含义清楚。不同搭配用于适度变化，不会凭空增加板块或让整篇反馈堆满图标。晚辅和班课默认仍使用自然段与必要编号。

写记录时，不必逐项组织语言。例如「基础题自己会做，变式找不到切入点，提醒用哪个性质后能继续」已经能说明掌握层次。生成会要求保留这种差异，让建议回应具体困难；未记录的进步、行为、作业和其他学生的情况不能从范文补入。

每位学生只需点击一次生成，后台会先生成初稿，再对照本次记录复核事实、掌握程度和学科建议。正常会调用同一配置模型两次，费用和等待时间相应增加；批量按学生逐个处理。

三个模块新生成正文中的 `【学生】` 由工作台在本机替换为亲切称呼。例如，李亦琳的正文使用「亦琳」，两字姓名「张瑶」仍使用全名，不会只剩一个「瑶」字；不能可靠拆分的姓名保留原样，无需另外填写。学生档案和名单仍保留全名；晚辅、班课复制文本顶部也保留全名，一对一使用下方的亲切称呼标题。称呼调整只用于新生成结果，不批量改写已保存或手写内容。

自动复核仍可能漏掉问题，生成后需要老师核对。如果初稿已生成但自动复核失败，页面会保留初稿并提示「自动检查未完成」，重点检查学生事实、掌握程度和学科建议后再使用。初稿和复核后的正文都不会自动变成已核对状态，不需要为此重新填写输入。

## 一对一标题

一对一最终复制时自动带标题，例如：

```text
亦琳第8次数学课（10.21）

正文……
```

正文上方显示可直接修改的完整标题，不再单独填写课次。日期取自上课时间，科目取自本次课程；两字姓名如「张瑶」仍完整保留。新建时根据上课时间最近的历史反馈接续，第 8 次之后是第 9 次，第 10 次之后回到第 1 次，按 10 次一循环。没有历史记录时默认第 1 次；旧记录缺少明确课次时，按已有课程顺序给出参考值。

默认值可以直接改成实际标题，修改后随记录保存在 SQLite 内。兼容旧课次信息和正文首行的课程标题，复制时只保留一个标题。标题暂时清空时保留本机草稿并提示填写，不会悄悄丢掉正文。

## 晚辅、班课导出 Word

在整班工作区点击「导出 Word」，输入文档标题后下载。正文按名单顺序排列为「学生全名：反馈内容」，每位学生单独成段；全文宋体、小四（12 磅），标题居中，学生姓名加粗，反馈内的换行保留。

导出采用点击时的当前正文，包含尚未保存的修改；没有正文的学生会跳过，待核对内容会提醒并一并导出。历史详情里的导出使用所选历史已保存版本。导出不调用 AI，不改变草稿或核对状态，也不会自动发送。文件可在 Word / WPS 中继续编辑。

## 输入、自动保存与刷新恢复

填写课程信息、学生观察和正文时，内容立即暂存在当前浏览器。字段有效且已有实际内容时，停笔约 1 秒自动保存到 SQLite，也可使用保存按钮。自动保存只更新页内状态，不再弹出全屏「正在保存」提示，保存期间可继续输入。失败或冲突仍会明确提示。自动保存只保存文字，不调用 AI，也不发送给家长。

| 页面状态 | 含义与处理 |
| --- | --- |
| 本机草稿已保留，等待保存 | 当前文字已暂存；停笔后自动提交，刷新回来可恢复 |
| 日期或学科等校验提示 | 先保留本机草稿，修正字段后再自动提交，不会因暂时清空日期而丢字 |
| 数据库暂未保存，稍后重试 | 后端离线或保存失败；保持页面开启，普通失败约 15 秒重试 |
| 已保存到数据库 | 当前提交已进入 SQLite，可以随正式资料导出备份 |
| 数据库有更新 | 暂停自动保存，保留本机文字，先处理版本冲突 |

刷新后回到原来的学生或班级，可以恢复尚未同步的草稿。查看历史详情不切换当前草稿；从详情选择继续编辑旧记录时，也会保留对应草稿。若正在生成或本机暂存失败，页面会提醒。当前草稿的保存状态显示在编辑区，「本机未同步草稿」列表只列出其他待同步草稿，避免填写过程中反复出现、消失。出现无法暂存提示时，文字仍在当前页面，但应先复制留存再刷新。

当本机草稿与数据库新版本冲突时，不会自动覆盖数据库。可以选择「保留这份文字，另存为新反馈」，或明确采用数据库版本；采用数据库版本会放弃该份本机草稿。

本机草稿限定同一浏览器、同一地址，`localhost`、`127.0.0.1` 和不同端口互不共享。清除浏览器数据会删除未同步草稿。它用于恢复编辑过程，正式资料仍以 SQLite 和导出备份为准。

## 个人风格参考

「个人风格参考」是选填项。展开后粘贴 1–3 份体现自己写法的满意范文，可用空行分隔，然后点击「保存风格参考」。页面显示「优先用我的风格」，后续生成优先学习你的结构、语气、篇幅和图标习惯，不再强套默认格式。一对一、晚辅、班课分别保存；同一模块内的所有学生和班级复用该模块的参考，不用每次填写。

例如，范文只有连贯自然段，生成也优先采用自然段；范文不使用图标，就不强加图标。使用图标的一对一范文可以采用含义相近的搭配变化。选择简短模式时，在该风格基础上压缩篇幅，不删掉关键事实。

保存后的参考用于后续 AI 正文生成，不会改写已有正文。未设置或清空后保存继续使用内置标准。个人写法不能覆盖事实和学科正确性，不应将范文里的学生表现、分数或任务当作本次事实；粘贴前先去掉姓名、联系方式等身份信息。

范文输入也会即时本机暂存，刷新后恢复并展开，但不会自动更新数据库；只有点击「保存风格参考」才影响后续 AI。数据库中的参考已有变化时，本机文字仍保留，可选择加载最新参考。

编辑后可「撤销修改」恢复已保存参考；清空输入并保存即可移除。未保存的风格修改会暂停 AI 按钮，先保存或撤销再继续。保存失败时输入保留，离开页面前也会提醒未保存修改。

## 输入示例

晚辅可以记录：“数学分式通分漏乘；周三主动订正；遇应用题先空着；约定先圈条件，再写第一步。”

这类记录比“表现一般，需要努力”更便于生成具体反馈。没有观察到的成绩、行为或家庭情况不要补写，生成后也要检查是否出现未经提供的细节。

## AI 配置与生成状态

在 AI 设置中配置 OpenAI 兼容服务地址、模型和该服务所需的 API Key，再测试连接。密钥保存在本机后端，不向前端回显，也不包含在工作台备份中。

未配置可用服务时不会伪装成 AI 已生成。可以继续保存事实、手工写正文，或使用明确标注为非 AI 的原始记录整理。

重新生成已有正文时，可以先比较候选内容，再决定替换或保留原文。修改生成依据后，原有核对状态会失效，需要重新检查。生成期间改变记录或停止生成，过时响应不会填入当前正文。

使用 AI 时，相关课程内容与学生事实会发送到配置的服务；有个人范文时发送当前模块已保存的参考，否则发送本模块内置匿名示例。程序不会主动附带姓名等档案身份信息；自行写进记录的身份信息仍会随文字提交。生成结果需要老师核对，实际验证范围见 [验证记录](VERIFICATION.md)。开发者可使用 [匿名评估脚本](../backend/evals/README.md) 检查输入到输出的效果；这不是日常生成前必须完成的步骤。

## 字数限制

课程内容、共用任务和关注重点各最多 5000 字；个人观察、后续建议及每科记录各最多 2000 字；每位学生的课后任务最多 8000 字；反馈正文最多 10000 字；每个模块的风格参考最多 12000 字。最多选择 10 门学科，每个学科名最多 50 字。

## 历史、复制与资料管理

在学生或班级反馈页下方查看「历史反馈」，默认展开，先显示最近 20 次，可点击查看更多。记录按反馈时间从新到旧排列：一对一使用上课时间，晚辅与班课使用反馈周期。补写旧记录不会改变它所对应的课程或周期顺序。

点击某次记录可查看已保存的教学内容、任务与反馈正文，展开「查看填写记录」可查看该学生的原始观察。详情只供查看，不替换当前编辑内容；关闭后可继续原来的填写。需要补写旧反馈时，再从详情选择「继续编辑」。已暂存的内容会保留，生成中、本机暂存失败或风格尚未手动保存时仍会提醒。

复制方式按入口区分：

| 入口 | 复制内容 |
| --- | --- |
| 一对一历史列表 | 该学生本次已保存的反馈标题、空行和正文 |
| 晚辅、班课历史列表 | 本次全部有正文的学生反馈，附各学生姓名和反馈周期 |
| 历史详情中的学生复制按钮 | 该学生在本次记录中的已保存正文 |
| 当前编辑页的复制按钮 | 当前有正文且已核对的学生反馈 |

历史记录中的待核对正文仍可复制，列表与详情会显示核对状态，复制后也会提醒先核对再发送。没有正文时复制按钮不可用。历史复制读取数据库已保存的版本，不包含当前未同步修改；复制不等于保存，也不会自动发送。浏览器不能直接写入剪贴板时，界面提供手动复制文本。

历史列表与详情均可删除。确认框会显示日期和范围：一对一删除该次课程；班级页删除本周期全班记录；某位班级学生的个人页仅清除该学生本次的填写记录和正文，保留其他学生及共用内容。学生档案不受影响，删除不可撤销。对应本机草稿也会处理，清理失败则不继续删除；数据库删除失败时保留原记录并恢复草稿。

- 学生录入仍在「学生管理」；原有资料和教学记录在「学生档案与笔记」。
- 学生列表可直接点击删除入口，确认一次后删除学生及关联记录；取消不会删除。

## 保存位置与旧数据

当前版本通过 Python 后端将工作台数据和三个模块的风格参考保存到项目中的 `.local/nookmi.sqlite3`。正常使用需要前后端同时运行，启动方法见 [README](../README.md)。

旧版浏览器数据可通过迁移入口导入，原 localStorage 副本保留，不会自动覆盖 SQLite。查找旧数据时应使用此前的浏览器和地址。

JSON 备份包含已同步到数据库的工作台数据和已手动保存的 `feedbackStyles`，不包含未同步本机草稿、AI 设置或密钥。恢复会整体替换工作台及风格参考，操作前先导出备份；旧备份没有风格参考时按未设置处理。

成功恢复备份或清空工作台时，会清理本机反馈和风格草稿，避免旧输入重新出现；取消或失败不会清理。多个页面同时修改时，后端拒绝过期保存，暂停自动提交并保留本机文字，需按提示读取最新数据后处理冲突。
