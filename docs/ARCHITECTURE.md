# 本地架构与数据说明

适用版本：v0.6.0。

## 组成

```text
浏览器中的 React 界面
        ├─ localStorage：未同步的反馈与风格输入
        │ 工作台读写、AI 设置、正文生成
        ▼
本机 Python FastAPI 后端
        ├─ SQLite：.local/nookmi.sqlite3
        └─ 配置的 OpenAI 兼容 AI 服务
```

前端负责学生与班级管理、即时本机草稿、自动保存、模块风格编辑、生成候选比较、核对和复制。后端负责持久化、数据校验、版本冲突检查和 AI 服务调用。

默认前端地址为 `http://127.0.0.1:5173`，后端地址为 `http://127.0.0.1:8000`。项目面向本机个人使用，未提供账号系统或云端同步。

## 启动与目录

首次在项目目录执行：

```bash
npm install
npm run setup:backend
```

日常使用执行 `npm run start`，或双击项目中的 `启动工作台.cmd`，同时启动前后端。需要分别运行时使用 `npm run backend` 与 `npm run dev`。

| 路径                                     | 内容                           |
| ---------------------------------------- | ------------------------------ |
| `src/`                                   | React 界面、前端数据类型及校验 |
| `backend/`                               | Python 后端及测试              |
| `.venv/`                                 | 项目专用 Python 环境           |
| `.local/nookmi.sqlite3`                  | 本地工作台数据库               |
| `.local/npm-cache/`、`.local/pip-cache/` | 项目依赖下载缓存               |

在当前 `E:\WorkSpace\Nookmi` 目录运行时，这些项目文件位于 E 盘。浏览器自身的用户目录仍由浏览器管理，不保证 C 盘零占用。数据库、密钥和本地缓存不应提交到 Git。

## 反馈数据

工作台继续使用 `schemaVersion: 1`，通过可选字段兼容早期备份：

- `FeedbackSession.brief`：周期起止、学科、共用课程内容、任务、重点和篇幅。
- `FeedbackEntry.observations`：每位学生的简短事实及分学科记录。
- `reviewed`：是否已核对。
- `generationSource`：`ai`、`manual` 或 `outline`，区分 AI、手写与原始整理。
- `generatedFrom`：生成依据的短签名，帮助判断事实改变后正文是否需要重查。
- `AppData.feedbackStyles`：可选的模块到参考文本映射，键为 `one-to-one`、`evening`、`course`。同模块共用，缺省为空。

一对一界面只有一个课后任务字段。读取旧双字段记录时，将 `brief.commonTasks` 与个人 `observations.tasks` 合并到后者，避免隐藏旧任务；晚辅和班课继续分别保留共用与个人任务。

个人记录以主输入框为常用入口，允许混写真实要点；亮点、困难、建议仍保留为选填细分字段，有旧内容时自动展开。此处简化填写方式，不迁移或删除既有观察字段。

正文为空时，仍可保存有共用内容或个人事实的草稿。只填写日期、选择学科或设置状态，不会被当作有效反馈内容。

前后端共同校验日期、长度、学生与班级关联。日期范围为 1900—2100 年，开始日期不得晚于结束日期；最多 10 门学科，每个名称最多 50 字。课程文本各最多 5000 字，观察、建议及每科记录各最多 2000 字，个人任务最多 8000 字，学生正文最多 10000 字，每模块风格参考最多 12000 字。

## 保存与迁移

SQLite 是正式资料的主存储。`feedbackStyles` 作为工作台偏好保存到同一数据库的 `workspace_preferences` 表，与工作台变更一起提交。localStorage 保存未同步的编辑草稿，同时保留早期版本的迁移副本；它不替代数据库和正式备份。

`src/feedbackDrafts.ts` 按模块、学生或班级、反馈 ID 分开缓存课程草稿，包含数据库基准快照、输入中的学科文字与选中学生。输入事件同步写入，允许日期暂时无效，恢复时再校验提交条件。有效且非空的反馈停笔约 1 秒写入 SQLite；普通失败在页面开启时约 15 秒重试，冲突时暂停。保存返回只清理对应已提交快照，保存期间的新输入继续保留。

`src/styleDrafts.ts` 按三个模块缓存 `draft` 与 `baseSavedValue`。风格只在本机自动暂存，明确保存才更新 `feedbackStyles` 和 AI 使用的参考。数据库新值与本机基准冲突时保留草稿，成功保存或明确撤销才清理相应副本；完成整体恢复或清空时仅移除三个模块的风格草稿键。

本机缓存受浏览器同源存储限制：同一浏览器、相同协议/主机名/端口才能读取；`localhost` 与 `127.0.0.1`、不同端口不共享。清除浏览器数据会删除未同步草稿。存储失败保留内存文字并提示，不假称已可靠暂存。

迁移需要明确操作，不会自动用旧浏览器数据覆盖数据库。JSON 导入仍是整体恢复；导出文件只包含已同步的工作台内容及已保存 `feedbackStyles`，不包含本机未同步草稿、AI 设置或密钥。旧备份缺少 `feedbackStyles` 时兼容为未设置；恢复或清空成功后清理本机草稿，失败不清理。

后端使用 revision 检查防止不同页面互相覆盖。前端反馈和风格保存共用保存锁；并发请求未保存的一方保留输入。版本冲突暂停自动保存；恢复草稿时若基准已变，也不自动覆盖，可选择将本机内容另存为新反馈或明确采用数据库版本。

## AI 调用

服务地址、模型和密钥在本机后端配置，密钥不会作为普通设置值返回前端。生成时，将对应反馈所需的课程内容、学生事实与已保存风格参考发送到所配置的服务。

| 接口 | 请求与返回 |
| --- | --- |
| `POST /api/ai/generate` | 接收 `module`、`brief`、`observations`、`grade` 和可选的 `styleReference`，返回正文、模型名；复核失败时另返回可选的 `reviewWarning` |

当前界面保留完整反馈正文生成，已移除 AI 推荐记录流程。自动保存只调用工作台持久化接口，不触发模型服务。

`services/feedback_standards.py` 保存每模块的写作要求与两组匿名输入/输出示例，`services/prompts.py` 仅组装当前模块的标准、示例、可选个人参考和最后一条当前事实。示例短输入由认可成稿逆向提炼，仅用于校准；不作为当前学生事实。标准说明见 [反馈写作标准](WRITING_STANDARDS.md)。

`brief.length` 继续使用兼容的 `standard` / `brief` 值；默认 `standard` 的含义改为按范文完整展开，信息少时仍简写，无统一 250–400 字目标。表单没有新增必填字段，数据库和既有备份无需因此迁移。

提示词将内置示例、个人风格参考与本次事实分开，要求保留掌握层次、具体卡点和不确定性，建议与困难对应。未提供个人参考时使用内置标准；提供参考时生成签名包含参考，风格变更会使旧请求和候选失效。前端对异步返回校验当前记录与请求版本，保留已有正文。

`services/feedback.py` 负责一次用户操作中的两阶段调用：先用 `build_messages` 生成初稿，再用 `build_review_messages` 对照当前事实复核并修正，正常会执行两次同一配置模型的 `AIProvider.complete`。复核请求把初稿当作可能有错的待检查文字，当前记录仍是事实来源。批量任务按学生逐个执行；费用和等待时间随两次调用增加，自动复核不保证正确。

首轮生成使用 40 秒、复核使用 25 秒的网络等待设置，均为每次网络操作的等待参数，不能相加理解为整体完成时限。前端生成请求允许等待 150 秒；服务延迟、连接过程和请求取消仍需按实际状态处理。

若第二阶段发生 `ProviderError`，服务保留有效初稿并附上安全的 `reviewWarning`，不回传上游原始错误。前端在生成状态或候选比较中显示提示，结果保持未核对；没有新增输入字段，持久化 schema 不变。模型使用 `【学生】` 占位；前端仅在接收新 AI 结果时本地替换为当前学生姓名，替换后再次检查长度，不将姓名加入请求，也不改写已有或手写正文。

没有可用服务时返回明确错误；非 AI 的原始记录整理始终单独标注。生成候选需要人工核对；复制和保存不会自动向家长发送消息。

## 生成质量评估

`backend/evals/feedback_cases.json` 保存匿名的代表案例、边界情况与人工核对要点；`backend/evals/evaluate_feedback.py` 使用同一请求 schema、提示词构建器和 provider，避免另起一套生成规则。运行命令见 [评估说明](../backend/evals/README.md)。

脚本默认仅校验用例、构建提示词，不读取 AI 配置或学生数据库，也不调用网络。使用 `--run` 时只读 AI 配置并调用已配置服务，支持 `--case` 和 `--limit` 控制范围；输入、输出、提示词摘要和耗时保存在 `.local/evals/`，报告不记录密钥或服务地址。脚本不导入工作台数据库、不写入学生资料。

字数、段落及占位符等机械信息只用于辅助检查，不能宣布文案质量合格；事实、掌握程度、建议对应和实际修改负担需要人工评价。成稿逆推输入与日常原始短记录的检验范围也应区分。

测试结果与实际验证范围见 [验证记录](VERIFICATION.md)，日常操作见 [课程反馈使用说明](FEEDBACK.md)。
